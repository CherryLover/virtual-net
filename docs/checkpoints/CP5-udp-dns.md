# CP5 第二批：SOCKS5 UDP 与 DNS 查询

> 状态：已完成，自动测试与实际页面验收通过（2026-09-07）。用户已授权按文档顺序实现；前置为已完成的 CP5 首批。本批仅实现 UDP 代理的 DNS 场景，整个 CP5 保持未完成。

## 范围与决定

- 保留直接 DNS 查询；新增显式选用 SOCKS5 的 UDP 查询。HTTP / CONNECT 不支持此操作，失败不回退直连，ping 和网站访问不自动改道。
- 代理新增可选 `proxy.udp: { enabled, port }`，旧文件缺失视为关闭；界面初始建议端口 1081。仅 SOCKS5 生效，TCP 监听与 UDP 中继端口分开配置，允许数字相同。
- 查询指定 DNS 服务器的 IPv4 地址与域名；未指定服务器时使用客户端原有 DNS 设置，不偷偷换为代理的 DNS。此处传送 DNS 查询，不是代理替网站解析域名。
- 每次验证建立独立 TCP 控制连接并检查 SOCKS5 与模拟认证，然后模拟 UDP ASSOCIATE，返回代理自身 IP 和配置的 UDP 中继端口。关联仅在该次验证有效。
- 顺序为 TCP 控制往返、认证、关联、客户端 UDP 到中继、代理向 DNS 查询并收回答案、UDP 中继向客户端返回。中继收到数据时不提前发出虚假 DNS 应答。
- 三条网络路径复用现有路由、VLAN、NAT 和访问规则。客户端与中继之间按外层 UDP 地址/端口检查，不跨连接使用 DNS 目标；本批不解析或改写 SOCKS 封装内的 DNS 内容。这不代表 SOCKS5 加密。中继与 DNS 服务器之间继续支持现有 DNS 应答改写。
- DNS 服务器答复但中继回不到客户端时整体失败，客户端结果不显示已成功获得答案；各段记录保留以供定位。
- 不实现任意 UDP 应用、UDP 分片、关联超时或 TCP 控制连接中途断开、多级代理、分流、IP 轮换、隧道、真实网络连接或部署。

## 实施步骤

1. 配置与导入：新增可选 UDP 配置，严格验证开关和端口；旧文件保持原行为。
2. 模拟与测试：建立关联、单向中继接收、DNS 出口与延迟返回；各段独立记录，失败立即停止。
3. 页面：代理配置增加 UDP 开关/端口；总验证窗口与单节点验证均提供 DNS 服务器及独立代理选择；查询不受网站端口或解析方式影响。
4. 回归：引擎与网页测试、构建、桌面/窄屏操作和保存恢复；通过后更新本页证据。

## 验收场景

对应 [测试表](../TEST-PLAN.md) T-CP5U-001 至 010。

- 成功场景必须有 TCP 控制、认证、关联、UDP 入口、DNS 查询及 UDP 返回的真实逐跳记录。
- 关闭代理、错误协议/认证、UDP 未启用、入口被拦、出口被拦和返回被拦分别失败并指向对应位置；后续段不得执行。
- 经代理到内部 DNS 与外部 DNS 均可验证；直接 DNS、网站代理、ping 不改变既有行为。
- 字段错误不能提交；刷新与 JSON 往返保留 UDP 配置；缺字段旧文件仍能加载。
- 桌面和窄屏都能配置、发起、查看结果；模拟不需要真实账号或外部网络请求。
