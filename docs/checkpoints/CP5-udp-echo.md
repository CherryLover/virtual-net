# CP5 第四批：UDP 回显服务

> 状态：已完成。对应 ROADMAP 中 DNS 之外的 UDP 应用，完整 CP5 仍未完成。

## 范围与关键设计

- 服务器服务列表增加传输类型：TCP 连接、UDP 回显。旧服务缺省仍为 TCP，同一端口允许分别配置 TCP 和 UDP，同协议端口不得重复。
- UDP 回显收到测试文本后原样返回，是明确的请求/响应模拟，不代表任意 UDP 服务都会应答。UDP 53 保留给已有 DNS 服务，不可用作回显端口。
- 新增独立的 UDP 回显验证，电脑、服务器和代理可发起。输入目标 IPv4、端口和测试文本，默认端口 7、内容 `hello`；UTF-8 内容限制 1–1024 字节，不支持分片。目标本批只支持 IP，不隐式进行 DNS 解析。
- 支持直接请求以及显式选 SOCKS5 代理，独立于网站与 DNS 的连接选择，不遵循网站分流规则。
- 代理复用已有控制连接、认证、UDP 关联、客户端中继、目标往返、最终返回六段流程。外层只检查中继地址/端口，出口检查目标地址/端口。
- 所有段复用现有路由、ARP、VLAN、NAT 和访问策略。未开放服务、错误协议、停服、入口/出口/回程被拦分别失败，不自动直连。
- 结果显示发送内容和实际收到内容；目标虽然产生回显但最终返回被拦时，不得显示收到回显。文本按普通文字展示，不作为 HTML 执行。
- 保留当前中间画布和轨迹动画；两个验证入口及服务器面板沿用现有紧凑表单风格。
- 不包含 NTP、SNMP、邮件、任意 UDP 协议解析、真实网络请求、吞吐/时延、关联超时、加密隧道、多级代理及部署。
- 延续当前引擎的设备间路径模型，不新增本机回环协议栈；直接访问自身地址明确提示不支持，不报成 ARP 故障。通过另一台代理访问自身服务仍走真实设备间路径。

## 实施步骤与完成标准

### CP5E-S1 服务模型与保存
扩展可选传输类型，严格校验协议及端口冲突，旧文件保持 TCP 行为；新增配置可保存、恢复与撤销。
验收：[T-CP5E-001](../TEST-PLAN.md)。

### CP5E-S2 直连与 SOCKS5 回显
明确的 UDP 服务处理，完整去回程；复用关联流程但不混用 DNS 内容。引擎测试成功、无服务、协议隔离、策略失败、NAT 回程、非法请求及原有 DNS 回归。
验收：[T-CP5E-002](../TEST-PLAN.md)、[T-CP5E-003](../TEST-PLAN.md)。

### CP5E-S3 页面与结果
服务器类型选择、两个入口、输入校验、发送/收到文本和分段结果。组件测试及实际浏览器验证直连/代理、失败定位、刷新保留和窄屏布局。
验收：[T-CP5E-004](../TEST-PLAN.md)。

- 全量 334 项测试（210 引擎、124 网页）、类型检查、代码检查及生产构建通过。保留已有的构建包体积提示。本批仅本地提交，未部署。
