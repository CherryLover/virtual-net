# CP5 服务器与代理服务

> 状态：首批已完成，整体页面验收通过（2026-09-07）。用户已明确左侧独立“代理”实体；整个 CP5 仍有后续能力，尚未完成。
> 前置：主机地址、逐跳记录、通用访问控制；依据 [设计方向](../design/network-model-and-ui.md)。

## 首批范围

- 服务器与代理均复用主机的单网口、自动或手动地址、网关与 DNS 能力。
- 左侧分别提供服务器、代理入口，支持添加、连线、配置、保存和诊断。
- 服务器提供可配置的服务端口、启停状态以及 DNS 服务设置。
- 代理首批支持 HTTP、CONNECT、SOCKS5 的 TCP 连接；入口协议与是否加密是不同概念。
- 单次网站访问明确选择直连或某台代理，填写模拟凭据与解析方式；设备级自动分流暂不隐式开启。
- 失败不自动回退直连。普通 ping 与路径测试不跟随应用代理。
- 本地解析先在客户端进行；代理解析发生在代理网络路径上，按协议能力约束。
- 分别模拟客户端到代理、身份验证、解析、代理到目标、返回结果；每段给出真实路径与失败原因。
- 策略只能看到所在连接的可见信息，不读取另一段连接的隐藏目标。

## 协议与解析决定

| 协议 | 首批行为 | 目标解析 | 默认目标端口 |
| --- | --- | --- | --- |
| HTTP 正向代理 | 代理代客户端建立目标 TCP 连接 | 代理解析，不提供客户端解析选项 | 80 |
| CONNECT | 通过代理建立指定目标的 TCP 连接 | 客户端先解析后传 IP，或代理端解析 | 443 |
| SOCKS5 | TCP 连接请求与独立目标连接 | 客户端先解析后传 IP，或代理端解析 | 443 |

端口可以修改；默认 443 不代表已模拟 TLS 握手。CONNECT 和 SOCKS5 不自动加密，首批不加入 SNI 或加密指纹判断。选择代理端解析时三类明文代理请求携带域名；选择客户端解析时先完成客户端 DNS，失败不建立入口连接，入口请求只携带 IP。

`proxy` 是专用单 `eth0` 节点，入口地址就是主机获得的 IP，监听端口与协议可配置。`server` 独立配置开放服务端口与 DNS。没有声明服务的普通电脑不会被误判为任意端口的网站服务器。

结果按连接阶段关联逐跳序号：客户端 DNS（选用时）、客户端到代理、身份验证、代理 DNS（选用时）、代理到目标、最终返回。入口握手与出口连接均走真实往返路径，目标响应再通过原入口连接返回客户端；不是添加固定的成功文案。

## 保存与兼容

- 代理配置、服务、策略与模拟凭据随本地保存及 JSON 导出保留，导入后可以重放模拟。
- 模拟账号密码以明文保存在浏览器数据和导出文件内。只能填写测试数据，不得输入真实凭据，不承诺保密存储。
- 只承诺新程序读取旧拓扑；旧程序可能拒绝新设备或忽略新字段，不承诺反向兼容。
- 服务器 DNS 记录是该服务自身应答，路径改写是经过设备对已有答案的修改，二者独立留记录。只显示真实查询服务与已有答案，不扫描无关节点猜测原始结果。

## 验收

对应 R-20260907-05 至 08，并补以下场景。

- 新增代理并接入网络后，HTTP、CONNECT、SOCKS5 首批能力逐一跑通。
- 入口端口关闭、协议不匹配、认证错误、DNS 无法访问、出口规则拒绝分别定位。
- 明确区分客户端与代理端查询；代理出口经过不同访问控制时按各自路径判定。
- 放入未使用的代理不影响直连；代理失败时不偷偷直连。
- 服务器端口开启和关闭分别成功与失败；模拟数据刷新、导入导出后保持一致。
- 浏览器显示两段连接与实际逐跳动画，不能只添加固定的“代理成功”文本。
