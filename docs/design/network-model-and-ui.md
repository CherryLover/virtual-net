## 2. 产品定位与统一概念

目标：让用户搭建网络，检查某次访问是否成功，看到实际路径、阻断位置和原因。不测真实设备，不承诺真实网速或现实网络的可达性。

| 概念 | 含义与边界 |
| --- | --- |
| 网络区域 | 办公网、访客网、云网络、外部网络等可命名分组；不直接决定放行或拒绝 |
| 网关 | 承担路由、地址转换或流量转发的设备；角色由配置与连接决定，不按软硬件或产品命名 |
| 访问控制 | 按规则放行、拒绝或处理访问；可表现为独立设备，也可能是主机上的能力 |
| 服务器 | 有地址、端口与服务的主机；不限定云厂商或部署方式 |
| 代理 | 可单独添加的实体，接受客户端连接，再向目标建立连接 |
| DNS 服务 | 负责解析、转发或按规则改写应答的服务 |
| 虚拟化主机 | 容纳虚拟设备、网桥和网卡；具体产品只用于可选示例 |
| 目标服务 | 用户想访问的服务，包含域名、地址、端口等信息；不等同于某个固定网站名单 |

默认文案采用“访问控制”“受限目标”“规则拒绝”“DNS 应答改写”“网关”“虚拟化主机”。具体地域、产品或真实站点可出现在明确标注的示例中，但不内置为全局判断依据。诊断可以准确说明“被防火墙规则拒绝”，不需要隐藏实际原因。

区分三个层次：设备与连线决定路径，规则与服务决定行为，画布位置与区带负责展示。不得通过移动节点或改变线形，悄悄改变模拟结果。

## 3. 访问控制与 DNS 的调整

### 需要替换的旧假设

| 旧方案假设 | 新方向 |
| --- | --- |
| 全图只取第一台启用的边界设备 | 按实际经过的设备逐台执行规则；支持多层访问控制，不设全局唯一边界 |
| 按特定地域决定是否过滤 | 按来源、目标、协议、端口等规则匹配；首批区域仅为展示标签，不自带阻断含义 |
| 未知区域直接放行 | 无命中规则时遵循明确默认动作；地址未知与访问被拒绝分别解释 |
| 只有 IP、域名黑名单 | 支持允许与拒绝、规则顺序和默认动作；高级匹配分阶段实现 |
| 只要图中有边界设备，DNS 就可能被改写 | DNS 服务自身应答策略与查询路径上的干预分开；不受未经过的无关设备影响 |
| 改写答案必然连接失败 | 可以失败，也可以连接另一服务或提示页；同时显示原目标与实际解析结果 |
| 图中有代理就不再警告 | 必须确认这次请求使用了代理，且代理入口与出口路径都可用 |
| 某类协议必然被封、另一类必然通过 | 结果由当前规则和可观察信息决定；“有识别风险”不能伪装成确定性模拟结论 |

### 已确定并实现的首批规则

- 启用规则按列表顺序首条匹配；默认动作初始为允许，可改为拒绝。拒绝终止本次模拟并给出设备与规则，不额外模拟丢弃超时、TCP reset 或 ICMP 拒绝消息。
- 主机入站、主机出站和经过设备的转发共用策略。每台实际经过的设备独立检查，路由转发依据当前连接在该设备处的地址，不使用全局第一台控制设备。
- “允许已建立连接返回”默认开启，仅放行此前允许的同一协议、地址和端口组合的应答；关闭后返回流量仍按顺序规则与默认动作检查，不开放无关连接。
- IP 条件支持单地址与 CIDR 网段；空值或 `*` 为任意。域名支持不区分大小写的精确匹配和 `*.example.com` 子域名匹配，后者不包含根域名；服务 DNS 记录只接受完整域名。
- DNS 查询携带域名；显式 HTTP 请求和代理端解析的代理请求可携带明文目标域名。客户端已解析后向代理传 IP，不在入口连接暴露原域名。不会让入口 IP 规则直接匹配另一段出口连接的目标地址。
- 首批不模拟 TLS/SNI 握手或加密 DNS；不会仅凭 TCP 443 推断域名可见，更不读取加密内容。HTTP、CONNECT、SOCKS5 均不因协议名称而自动获得加密保护。
- 服务器 DNS 可按本地记录回答，缺少记录时按配置经真实路径查询上游。其记录是该服务自己的应答，不扫描无关互联网目标猜测“原答案”。路径设备只改写实际经过的 DNS 返回应答，分别记录已有答案、改写后地址和设备；改写后网站连接继续访问实际地址。
- 多个目标域名可共用 IP；同一目标列表的域名和标识需唯一。一个域名多地址、DNS 缓存、递归解析全协议与加密 DNS 留待后续。

## 4. “代理”实体

### 用户可见的体验

左侧设备库中有独立的“代理”入口，可搜索、点击添加或拖入画布。加入后是能选中、命名、连线、配置、删除的节点，具有自己的连接状态和诊断结果。它不是示意图标，也不是自动生效的全网开关。

左侧已按终端、网络设备与服务职责分组，提供独立“代理”入口，不要求用户从空白服务器猜测如何开启代理。搜索、点击添加和拖拽添加复用设备库行为。

### 首批配置

| 配置组 | 内容 |
| --- | --- |
| 网络连接 | 地址、掩码、网关、DNS、接线端口；与普通主机复用能力 |
| 代理入口 | HTTP / CONNECT / SOCKS5、监听端口、启停状态；入口地址复用主机获得的 IP，不另设监听地址别名 |
| 身份验证 | 无认证或测试账号密码；明确只填写模拟凭据，不收集真实密码 |
| 目标解析 | 客户端已解析后传 IP，或将域名交给代理解析；按协议能力限制 |
| 出口 | 首批由代理直连目标；上一级代理、多级连接尚未实现，不显示虚假可用选项 |
| 访问范围 | 可访问的目标与端口、连接来源限制；与通用访问规则衔接 |

“IP 代理”不作为独立协议：IP 与端口表示入口地址，实际行为由 HTTP、SOCKS 等协议决定。IP 池与轮换没有在本轮确认，不纳入首批要求。

### 协议与行为边界

- 首批已覆盖 HTTP 正向代理、HTTP CONNECT 与 SOCKS5 的 TCP 连接；UDP、中转链、网络隧道、设备级分流和 IP 轮换属于未实施的后续范围。
- CONNECT 不等于客户端到代理的传输一定加密；SOCKS5 本身也不提供加密。协议、传输保护和出口分别表达。
- 显式代理的应用请求与普通网络测试分开。配置应用代理，不得让普通 ping 自动走代理。
- 客户端按单次访问明确选择直连或代理；没有设备级自动分流，也不存在隐式规则优先级。
- HTTP 正向代理由代理解析目标，默认目标端口 80。CONNECT / SOCKS5 默认目标端口 443，可选择客户端先解析后传 IP，或由代理经自己的网络解析。目标端口可显式修改，不等于模拟 TLS 内容。
- 完整过程至少区分“客户端到代理”“代理身份验证”“代理解析目标”“代理到目标”“返回结果”。每段产生可定位的原因。
- 代理与网络隧道不是同一回事；代理通常建立另一段连接，不要全部伪装为原始 IP 包的简单封装。
- 任一阶段失败即终止，不自动退回直连；首批不提供回退策略开关。

### 已采用的内部表示

采用独立 `proxy` 节点，单 `eth0` 网口，内部复用电脑与服务器的地址分配、路由和诊断能力。`server` 提供可配置监听端口与 DNS 服务。多个关联连接记录各自起点、目标、逐跳范围与成败：客户端解析（选用时）、入口、身份验证、代理解析（选用时）、出口、最终返回。最终响应通过原入口连接返回客户端，不把两段连接伪装成一个 IP 包。

## 5. 页面布局与交互

### 设计方向

采用工作台式网络编辑器：信息密度适中、操作分组明确、选中状态清楚。保留中间无额外装饰框的主画布，不改成首页、仪表盘或卡片堆叠，不用大面积装饰挤占操作空间。

已延续浅色中性底色与状态语义，统一间距、字号、图标与表单样式；外围工作台和右侧面板已重排。以下为当前实现及最终交互验收要求，不把“已改样式”等同于所有操作已经验收。

### 顶部工具栏

- 文件操作（新建、导入、导出、示例）与编辑操作（撤销、重做）分组；验证保留次要图标“选择起点验证”，方便不选节点时发起单次验证，不表示全网扫描。设备自身入口保留。
- 保存状态清楚但不抢占空间；名称框桌面上限 168px、手机上限 112px，不随宽屏无限伸展，长名称省略且不挤压其他按钮。
- 常见工具使用标准图标与悬停提示；明确命令允许图标加文字。沿用已有图标体系或统一引入图标库，不混用字符图标。
- 次要操作收纳到菜单；窄屏折叠而不是横向溢出。

### 左侧设备库

- 支持分组、搜索与收起，保留点击添加和拖拽添加的便捷方式。
- 代理与其他设备使用一致的图标、尺寸、选中和拖拽反馈。
- 当前未实现的设备不能伪装成可用入口；说明范围放在文档或明确的未开放状态中。

### 中间主画布

- 保留平移、缩放、框选、批量移动、节点配置、路径播放的工作方式。
- 改进选中与悬停反馈、工具命中区域、端口与连线标签；不随便改已有手势。
- 两侧面板收起或展开后，画布保持合理可用面积，不强制重置用户视角。
- 现有 240px 左栏与 320px 右栏只是实现现状，不作为新设计的固定要求。
- 步骤序号锚定在节点上方 36 画布单位，避开端口和 VLAN 标签；宽度不超过节点，多个序号可换行。独立叠加层高于选中节点，每个序号仍能打开对应步骤详情。播放条与缩放控件错开，播放期间适配画布留出更多空间。

### 右侧节点操作面板

- 顶部稳定显示设备名称、类型、状态和关闭入口；配置区域独立滚动。
- 已按“配置 / 端口 / 验证”组织，不同设备显示适用内容；非验证起点仍可查看结果。
- 常用配置优先，高级项渐进展开；开关、选项、数值分别使用合适控件。
- 错误紧邻字段，点击诊断结果能打开对应分组并滚动定位，不被折叠项隐藏。
- 文本输入在失焦或 Enter 时校验并提交；无效内容显示字段错误且不写入已生效配置。开关和选项即时提交，不另设整页“应用”。
- 切换节点时重新挂载该节点面板，临时内容不串用；合法失焦内容已提交，无效未提交内容离开后丢弃，原配置保留。
- 单节点、多选、连线、未选中各有对应内容；配置与验证结果之间能方便往返，不能只能点空白处才找回结果。
- 删除、恢复默认等破坏性操作与常用操作分开；保持撤销能力。
- 桌面采用可收起两侧面板；宽度小于 760px 时默认收起，设备库和属性面板互斥展开。390px 窄屏流程已验收，未做真手机硬件验证。

## 6. 连线与端口

### 当前实现

- `apps/web/src/canvas/DeviceEdge.tsx` 保留自动贝塞尔曲线，并增加选中后的两个控制柄、恢复自动线形与拖动提交。
- 普通交换机默认上下分配端口，每个逻辑端口可独立选择上、下、左、右展示侧，不增加物理端口数量。
- `PortHandles.tsx` 同一端口的 source / target 柄表示拖线方向，不表示两个独立物理端口。
- 路径动画当前沿实际 SVG 连线取点；新增线形必须保留这一契约。

### 曲线拖拽要求

- 选中连线后出现可拖拽控制柄，调整贝塞尔曲线以手动避开节点和标签；未选中时不铺满控制点。
- 默认仍自动生成合理曲线；提供“恢复自动线形”。本轮不承诺全自动避障。
- 控制柄、连线、节点拖动、画布平移的命中与手势不冲突；一次拖动完成对应一次撤销。
- 线形调整后标签位置仍合理，动画沿新曲线往返，错误与选中高亮覆盖同一路径。
- 缩放、平移不改变保存值；控制点分别保存相对起点和终点的偏移，移动单个节点只带动对应控制点，整体移动带动整条曲线。
- 手动线形属于展示数据：应保存、导出、导入、撤销与重做，但不改变连接关系或让验证结果过期。
- 老文件没有线形数据时使用自动曲线；删除连线后清理相应展示数据。

已采用三次贝塞尔曲线的两个控制柄与端点相对坐标；一次完整拖动记录一次历史操作，标签跟随曲线中点，路径动画继续沿实际 SVG 线形。拖线身、多折点和全自动避障不属于本轮。

### 上下端口与同级连接要求

- 普通交换机也应能从上侧和下侧方便接线，不再依赖“端口超过 16 个”才开放上侧。
- 展示位置不改变端口身份、VLAN、占用情况和连接语义；一个物理端口仍最多连接一根线。
- 同级设备可选择左右出线，避免被强制从底部绕行；上下侧同样可选，已完成浏览器操作验收。
- 端口名称、连接状态、VLAN 信息应可识别；高端口数时避免节点无限变宽和标签重叠。
- 已有连线迁移后端点仍指向原端口，不得为换边删除重建物理端口。

已采用“同一逻辑端口选择展示侧”，不复制上下视觉入口。端口 ID、VLAN、占用与连线关系不变；切换边不删除重建物理端口。

## 7. 技术边界与兼容要求

- 展示配置与模拟配置分离：结构指纹排除曲线、端口展示侧和区域标签，访问策略仍参与指纹。修改展示不使结果过期，修改连接或规则会使结果过期。
- 数据结构、导入校验、自动保存、历史记录、画布映射与动画需一起检查，不能只改 Edge 或节点组件。
- 兼容只承诺新程序读取旧文件：旧文件没有线形和展示侧时按自动布局，没有策略时维持原有放行逻辑。格式版本保留现有版本；旧程序可能拒绝新设备或丢失新字段，不承诺旧程序读取新文件。
- 模拟凭据随浏览器本地保存和 JSON 导出明文保留，导入后可重复模拟；只允许测试数据，不得填写真实账号密码，也不提供保密存储承诺。
- 代理结果以 `connections` 将逐跳序号关联到独立阶段，认证失败与解析失败均保留所在阶段；实际包路径和结果动画复用现有决策记录。
- 独立访问控制是透明双口节点；主机与现有路由设备共用策略，但不另建全功能路由型安全设备，不声称覆盖所有现实设备形态。
- 本轮不新增后端、真实代理连接、真实流量转发、账号系统或部署任务。
