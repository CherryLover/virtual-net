# 学习模块与网络小课程需求

> 总纲：[ROADMAP.md](../../ROADMAP.md)。记录日期：2026-09-08。
> 状态：需求设计，未实现、未排期。用户已确认面向零基础人群，以小课程、实际配置和模拟验证学习网络。
> 本文给出完整课程体系的首版设计，不表示所有课程必须同时发布，也不改变 CP5 → CP6 → CP7 的现有执行顺序。

## 1. 定位与完成目标

让没有网络基础、但想了解网络的人，从连接两台电脑开始，逐步能够搭建并解释一个小型办公室网络。不是认证题库，不要求购买设备、安装软件、背命令或使用真实账号。

“实际配置”指操作画布上的设备，填写地址、网关、服务和规则，由已有模拟引擎计算结果；不是点选预设答案，也不是连接真实网络设备。课程中填写正确值后必须真的产生相应行为，故障也必须真的影响模拟结果。

学习完成的判断是“做出来并观察到结果”，不以读完页面、播放动画、耗时或点击下一步替代。允许满足目标的不同配置，不要求逐字段等于参考答案。

### 1.1 目标用户与教学方式

- 首次出现专业词时，用一句日常语言解释，再附名称；先讲问题，再引入术语。
- 首发每节约 5–10 分钟，进阶约 10–15 分钟，综合实验约 15–25 分钟。时长仅是内容设计目标，不限时、不计排名。
- 一节只新增一个主要概念；复杂实验可以复用前面学过的概念，但不得突然要求未教过的操作。
- 教学说明放在课程区域，工作台工具仍保持简洁。学习模块需要说明内容，不等于在普通工作台增加大段教学文字。
- 先给具体值和原因，再逐步减少提示；核心路径不以二进制换算、七层模型或大量缩写开场。
- 错误是练习的一部分，不扣分、不清空进度。课程不把“访问失败”一概当错，例如隔离任务必须证明某些访问确实失败。

### 1.2 非目标

不做真实设备远程配置、真实邮件发送、实网探测、联网实验后台、MCP、登录和云端同步；不承诺替代真实设备训练或完整复刻某厂商模拟器。证书、考试、排行榜、社交和 AI 教师不是本需求范围。

## 2. 能力依据与发布状态

以下“现有能力”仅表示本地代码和检查点已有支撑，不表示课程已经制作、页面已上线或所有设计组合已经验收。每节发布前仍须制作独立实验与自动测试。

| 能力 | 当前依据 | 课程使用边界 |
| --- | --- | --- |
| 设备、接线、IPv4、网关、DHCP、NAT | [CP1](../checkpoints/CP1-lan-basics.md) | 逻辑可达性，不模拟线路质量和真实租约计时 |
| 交换机、VLAN、AP、光猫 | [CP2](../checkpoints/CP2-switching-and-devices.md) | AP 是简化桥接；不教无线信号、加密和漫游；环路不做生成树收敛 |

## 3. 模块产品需求

### 3.1 入口、导航与课程页

- 与“工作台”并列增加“学习”入口，不替换现有工作台或自动打开课程。
- 学习首页按单元显示目标、课程数、预计时长和本地进度；提供“继续上次学习”。首发只展示可用单元，规划课程不出现可点击的空实验。
- 课程允许浏览，推荐顺序用前置关系提示；跳学前说明需要哪些知识，不强制通过所有前课才允许进入。
- 桌面课程页以原主画布为主，配合紧凑课程步骤区和既有设备配置面板。学习说明、配置与结果不能互相盖住。
- 小屏按“任务 / 画布 / 配置与结果”切换，保留当前步骤和选中设备；不把三个长面板挤在同一屏。
- 每课固定节奏：情境与目标 → 简短示例 → 动手配置 → 运行观察 → 小挑战 → 结果回顾。
- 完成后显示实际达成的目标、仍可探索的变化，以及下一节入口；不以弹窗强行跳课。

### 3.2 实验与工作台隔离

- 每课从不可修改的版本化初始样板创建独立实验副本，工作台和不同课程使用独立保存位置。
- 当前工作台保存为 IndexedDB `virtual-net/topologies` 中的 `current` 记录，学习隔离是待开发能力，不能仅换入课程图后继续让既有自动保存写 `current`。课程草稿按课程 ID/版本独立存储，进度另存；切换前等待当前保存完成，失败时留在原上下文并允许重试或备份。
- 进入、退出、切课、刷新和重置课程都不得覆盖用户工作台；切回工作台时恢复原图、视口及保存状态。
- 默认保存每课当前实验、步骤、提示使用情况与完成记录。保存失败、浏览器空间不足、数据损坏必须明确提示，不能显示“已保存”。
- “重置实验”确认后只恢复当前课程初始配置，并清除本次验证状态；保留曾经完成的历史记录。“清除学习记录”是另外的明确操作，不清除工作台。
- “另存到工作台”保存为独立网络图，生成独立身份或副本，先确认未保存工作台内容；课程来源作为可选元信息，不把课程限制带到自由编辑中。
- 若首发工作台仍只能保留一张当前图，“另存”先完成原图可恢复备份并明确确认替换；备份失败则不替换，不以功能名称暗示已经支持多图库。取消后两边均保持原状。
- 多标签页修改同一课程时依据修订号发现冲突，不静默以后写覆盖先写；提供保留当前副本或载入另一版本。读到较新且不兼容的记录时先保护原数据，提示升级或导出，不能当损坏记录直接重建。
- 首发提供独立的学习备份文件导入/导出，包含课程版本、进度和实验副本，不混进普通拓扑 JSON；导入前预览影响并确认，不静默覆盖现有记录。
- 学习备份导入采用总需求的[导入前分步检查](../../ROADMAP.md#import-checkpoints)：依次检查文件、内容、节点配置、连接与关联，再确认导入；额外检查课程身份、版本、进度与实验副本对应关系。故障练习中的可编辑配置错误仅提醒，不要求网络连通或已通过课程；结构损坏或不兼容则阻止，未识别的课程不静默丢弃。确认前保护原学习记录，失败不部分写入，不影响自由工作台。
- 本地保存不等于永久备份。首次需要说明清除网站数据、更换浏览器或设备后不会自动同步；学习不依赖联网账号。

### 3.3 引导、提示与参考做法

- 步骤能定位到对应设备、端口或字段，滚动到可见位置；高亮不遮挡输入、不强制移动已开始拖动的画布。
- 提示分三级：先指出值得检查的现象，再提示概念/位置，最后给出具体配置值。各课下文按“提示”给出递进线索。
- 参考做法可在任何时候主动查看，不惩罚用户；查看不自动替用户配置。应用参考配置必须确认，作为一次可撤销操作，仍须重新运行验证。
- 小挑战默认基于独立挑战副本，不破坏已通过的基础实验。返回基础实验恢复原配置，挑战成功分别记录。
- 提供术语短释义与本课示意，不引导用户离开页面阅读长文章才能继续。

### 3.4 判定、结果与防止误导

- 每课配置一组明确检查：必要结构/配置约束、应该成功的验证、应该失败的验证、必须观察的证据。负向检查的“预期失败”计作目标达成。
- 不比较整张图与标准答案；节点可改名、移动、调整连线形状，等效地址方案与合法端口替代按课程约束接受。
- 实验目标角色使用稳定身份关联，不靠显示名称查找；用户替换角色设备时须支持重新绑定或给出明确缺失提示。
- 通关不能只检测一次成功。例如“禁止访客访问内部服务”同时检查员工仍能访问，防止拔线或停服被误判完成。
- 验证取当前配置快照，配置变化后旧结果标为过期；旧成功不能给新配置自动通关。重复检查应确定且不消耗不可恢复的运行状态。
- 观察题可以要求点开一条实际决策记录，展示源地址或拒绝原因；自述仅辅助学习，不用关键词匹配冒充理解判断。
- 未支持、无法确定、运行出错和预期失败分开表示；“未支持”不能通关。判定器本身必须有绕过目标的反例测试。
- 已通过记录保留对应课程版本。内容升级不静默改写旧实验；先备份旧副本，再由用户选择继续旧版或开始新版。破坏性升级标注“新版待练习”，不抹掉历史完成。

### 3.5 可访问性与安全

- 全流程有键盘操作路径；接线提供选择两端设备和端口的非拖拽替代，不能只支持精确拖动。
- 字段有可读标签，提示与结果可被读屏软件读取；状态使用文字/图标而非只用颜色。
- 支持放大与减少动画，不播放动画也能从逐跳记录完成课程；不以反应速度或颜色辨认作为通关条件。
- 所有凭据均为明确的模拟值；只使用私有地址、文档用途地址和 `.example` 域名，不引导填写真实密码。
- 学习页不请求实验中的真实地址；文本回显和未来邮件内容按普通文本展示，导入内容不可执行脚本。
- 普通导图和分享卡片是另外的需求；未实现前课程不依赖它们。分享前需要检查画布上的名称、地址与标签，但本模块不上传课程数据。

### 4.2 可复用拓扑与具体值

课程可引用下表，引用即继承全部明确值；未列出的访问规则关闭，主机使用静态地址，服务关闭，连线启用。所有 `/24` 在输入框使用 `255.255.255.0`。以下是参考解，不要求用户地址与之一字不差。后文两段缩写如 `.10.30` 表示 `192.168.10.30`，单段缩写如 `.30` 指当前所述主机网段的最后一段；正式课程输入提示必须展示完整地址，不要求新手自行推断缩写。

| 样板 | 设备、接线与配置 |
| --- | --- |
| P1 双机局域网 | PC-A `192.168.10.10/24`、PC-B `192.168.10.20/24` 接交换机 S1 的 1、2 口；网关/DNS 留空；S1 端口默认 VLAN 1 |
| P2 小办公室 | P1 加 R1，S1 的 8 口接 R1 `lan1`；R1 LAN `192.168.10.1/24`，DHCP 初始关闭，NAT 开；电脑网关 `192.168.10.1`、DNS `192.0.2.53`；R1 WAN 接互联网 I1，WAN 自动获取；I1 接入 `203.0.113.1/24`，池 `203.0.113.2–203.0.113.20`，DNS `192.0.2.53`，目标 `site.example → 198.51.100.80`，TCP 80/443 开启 |
| P3 办公服务 | P2 加服务器 SVC `192.168.10.30/24`，网关 `.1`，接 S1 的 3 口；TCP 8080 开，DNS 开，记录 `desk.example → 192.168.10.30`，上游 `192.0.2.53`；电脑 DNS `.30`；需回显的课程另开 UDP 7 |
| P4 两个网络 | P2 的 PC-B 改接 R1 `lan2`；该口预配 access VLAN 20、对应子接口 `192.168.20.1/24`；PC-B 改为 `192.168.20.20/24`、网关 `192.168.20.1`。VLAN 1 仍经 `lan1` 接 S1；额外地址池关闭。A04 仅解释“两侧属于两个网络”，C04 再展开 VLAN 配置 |
| P5 两组交换网络 | S1 1、2 口 access VLAN 10，接 PC-A `192.168.10.10/24` 和 PC-B `192.168.10.20/24`；3 口 access VLAN 20 接 PC-C `192.168.20.10/24`；主机初始无网关。扩展 S2 时用双方 8 口 trunk，native 1，允许 10、20；S2 1 口 access 10 接 PC-D `192.168.10.40/24` |

### 4.3 每课记录规范

下面每课的“检查”同时规定正反结果，“完成”是通关条件，“挑战”是单独挑战目标。提示以三个层次给出。前置为推荐知识关系；进入实验不沿用上一课未完成图，而从本课固定样板开始。

## 5. 首发：从零连接

### L-A01 先把设备连起来

- 目标/前置：认识电脑、交换机、路由器职责；无前置。情境是让同桌两台电脑进入同一个小网络。
- 实验：P1 的两台电脑预填地址，S1 与两台电脑未接线；路由器仅在课程插图中解释，不强迫拖入无用设备。
- 配置步骤：查看三台设备名称；PC-A `eth0` 接 S1 1 口，PC-B `eth0` 接 S1 2 口；从 A 验证 B。
- 检查：接线前 A 到 B 失败；两条线完成后成功；移动 S1 后结果不变。解释位置不是网络距离。
- 提示：先看有没有完整线路 → 找空闲端口 → 给出上述两条端口对应关系。
- 挑战：移除 B 的连线后，换到 S1 3 口恢复；完成条件是两机连通且路径经过 S1，不要求指定交换机端口。
- 完成：基础连通检查通过，用户打开至少一条经过交换机的记录；不要求从交换机发起 ping。

### L-A02 给两台电脑填写地址

- 目标/前置：理解地址用于区分设备；前置 A01。情境是两台电脑接好了线，但还没有地址。
- 实验：P1 接线完成，主机地址留空，改为手动配置。
- 配置步骤：A 填 `192.168.10.10`，B 填 `192.168.10.20`，都填掩码 `255.255.255.0`；网关/DNS 暂空；双向验证。
- 检查：缺少有效地址不能通过；双向成功；挑战副本把 B 改成 A 地址，配置检查必须指出重复，不能只看一次 ping。
- 提示：每台电脑需要不同号码 → 前三段与掩码先保持一致 → 给出 `.10` 和 `.20`。
- 挑战：B 换成同网段另一个合法地址，重新验证；不接受网络地址、广播地址或重复地址。
- 完成：两台地址合法且唯一，双向连通；不把“所有网络掩码都是 /24”作为课程结论。

### L-A03 接了线，为什么还是找不到

- 目标/前置：认识子网决定哪些地址被看作同一网络；前置 A02。

- 配置：员工与 SVC 使用 VLAN 10、网段 `.10.0/24`，访客 VLAN 20、`.20.0/24`；R1 子接口各 `.1`，trunk 放行；SVC `.10.30`、TCP 8080、DNS `desk.example`；R1 或 SVC 加拒绝访客到内部服务的规则，仍允许外部访问及必要 DNS。
- 检查：A/B 可访问 `desk.example:8080`；C 不可访问 SVC 8080，但 C 可访问 `site.example:443`；各主机地址唯一，路径不靠拔线实现隔离。
- 提示：按地址、网关、服务逐项检查 → 用访问矩阵找失败项 → 展开上述参考配置，允许等效的合法网段和规则位置。
- 挑战：给员工增加 PX，仅外部网站按规则经 PX，本地服务仍直连，访客权限不变。
- 完成：全部正反检查通过并另存一份可继续编辑的工作台副本；不要求分享图片或云端链接。

### L-F02 接手一个出故障的办公室

- 目标/前置：独立诊断并避免修复一个问题破坏另一个；前置 F01。
- 实验/配置：使用 F01 的挑战完成参考图，不依赖用户是否做过可选挑战。固定 PX 为 VLAN 10 的 `192.168.10.40/24`、网关 `192.168.10.1`、DNS `192.168.10.30`，SOCKS5 1080 无认证；员工规则 `site.example:443` 经 PX 代理端解析，本地 `desk.example:8080` 直连。注入四个固定故障：trunk 漏放行 20、A DNS `192.168.10.99`、SVC 8080 停服、PX 关闭；分别恢复 VLAN 20、DNS `192.168.10.30`、服务和 PX。
- 检查：每修复一项重跑访问矩阵；最终员工服务、访客外部访问、访客内部拒绝、员工代理路径全部符合目标。
- 提示：先排查影响范围最大的共同路径 → 对照接入/解析/服务/代理分段 → 逐个揭示对应字段，不一次清空所有规则。
- 挑战：在独立副本制作其中一个已学故障，观察检查结果改变，再撤销并恢复全部通过。
- 完成：整体矩阵通过，无靠停用所有策略绕过隔离；题库扩展时每个故障版本必须有确定初始状态与独立测试。

## 11. 规划课程：网络扩展

本单元的配置是教学目标草案，不是当前可填表单或已经确定的协议字段。依赖能力先完成设计与验收，再把草案落实为可运行样板；不能让课程需求自行扩大 CP5、CP6、CP7 已约定边界。

### L-G01 在两个网络之间建立一条隧道

- 状态/目标/前置：规划，依赖 CP5 隧道及明确的路由/封装模型；前置 B03、E01。理解内层目标和外层承载不同，不把代理当作隧道。
- 拓扑/配置草案：站点 A `192.168.10.0/24`、B `192.168.20.0/24`；两端外部地址 `203.0.113.2`、`198.51.100.2`；模拟隧道端点 `10.255.0.1/30`、`.2/30`，双方指定对端及对侧网段；具体承载协议、身份和接口字段待能力方案确定。
- 检查：隧道建立且双侧路由正确后跨站点服务成功；关闭一端或阻断承载后失败；本地局域网仍正常。记录区分外层与内层，不用图上虚线冒充封装。
- 提示：先查外层端点 → 再看两端设置和对侧网段 → 展开双方参考值。
- 挑战：只发布 B 的服务网段，不使未授权网段自动可达。
- 完成/解锁：具备双向路径、承载失败、路由限制三组自动测试；若还未定义加密过程，本课不得把“隧道成功”叫作“加密成功”。

### L-G02 经过两台代理的访问

- 状态/目标/前置：规划，依赖 CP5 多级代理；前置 E02、E03。理解每一段都有自己的入口、认证与出口。
- 拓扑/配置草案：P6 加 PX2 `.10.50:1080`；A 指定 PX1 `.40:1080`，PX1 上游设 PX2，PX2 访问 `site.example:443`；先限定两跳 SOCKS5 TCP，禁止循环。
- 检查：成功显示 A→PX1→PX2→目标；停 PX2、错第二跳模拟密码分别准确定位；第一跳正常不能直接通关。
- 提示：找第一段失败 → 核对该段上游与认证 → 给出 PX1/PX2 对应配置。
- 挑战：设置 PX2 又指向 PX1，系统应明确拒绝环路，而不是卡住或无限转发。
- 完成/解锁：多跳、认证归属、DNS 解析位置和循环处理先有明确引擎语义，课程不依赖尚未承诺的 IP 轮换。

### L-G03 一台主机里，也可以有多个网络设备

- 状态/目标/前置：规划，依赖 CP6；前置 C04。理解虚拟网卡、网桥和外部接口的关系。
- 拓扑/配置草案：虚拟化主机 H 物理口接 P2 S1，网桥 br-office 接物理口和虚拟服务器 V 网卡；V `192.168.10.60/24`、网关 `.1`、TCP 8080 开；A 访问 V。
- 检查：桥接正确后可达；移除 V 到网桥的内部线后失败定位内部连接；移动外部画布位置无影响。
- 提示：沿外部到内部路径看 → 找网卡接在哪个桥 → 将 V 网卡接 br-office。
- 挑战：添加隔离网桥 br-lab 和第二虚拟设备 `.20.60/24`，证明仅存在于同一主机不会自动互通。
- 完成/解锁：内部视图、保存恢复、桥边界与故障定位已经实现；不把视觉分组当作虚拟网桥。

### L-G04 从另一个网络访问内部服务

- 状态/目标/前置：规划，依赖 CP7；前置 B03、D04。理解外部地址、端口映射和目标回程。
- 拓扑/配置草案：内部服务器 `.10.30:8080`，路由器外部文档地址 `203.0.113.2`；映射 TCP 外部 18080 到内部 `.30:8080`；外部客户端通过明确外部网络路径访问 `.2:18080`。
- 检查：正确映射与允许规则下成功；错误内部端口失败；换成上游共享地址 `100.64.0.2` 且未提供上游入站能力时不能直接访问。
- 提示：先看外部能访问哪个地址 → 检查映射目标和服务 → 给出 18080→8080；不建议在真实路由器照抄开放。
- 挑战：只允许指定模拟外部客户端访问，另一外部客户端必须被拒绝。
- 完成/解锁：公网/共享地址判断、DNAT、回程与来源限制已有测试；不把文档地址当作真实公网服务，也不自动引入内网穿透功能。

## 12. 规划课程：企业服务体验

本单元是零基础课程之后的可选延伸，仍用小任务而非完整协议教材。所有账号和业务数据都是本地模拟；端口号只是参考约定，不能只测端口便声称业务完成。

### L-H01 连通之外，还要检查安全连接条件

- 状态/目标/前置：规划，依赖 TLS 模拟范围获批；前置 D01、D03。理解名字、证书和加密方式的匹配。
- 拓扑/配置草案：P3，`secure.example → .30`，服务 TCP 443；模拟证书名称 `secure.example`、测试信任根 `Lab-CA`，客户端信任该根；有效期使用课程固定时钟，不依赖电脑日期。
- 检查：名称、有效期和信任条件符合时握手通过；名字不符或过期时，即使 TCP 可达也失败；不执行真实 TLS。
- 提示：先区分连接还是握手 → 看失败的证书条件 → 给出正确名称/信任根/固定日期范围。
- 挑战：为第二域名配置覆盖它的模拟证书，保留原域名成功。
- 完成/解锁：证书字段、固定时钟、错误分类与握手判据已确定；不能通过“443 打开”通关。

### L-H02 发送第一封模拟邮件

- 状态/目标/前置：规划，依赖 SMTP 本地投递；前置 D01、D03。区分连接、认证、提交和投递。
- 拓扑/配置草案：P3 SVC `.30`，`mail.office.example` 指向 `.30`；模拟 SMTP 提交端口 587，邮箱 `alice@office.example`、`bob@office.example`，密码均为 `demo-only`；A 以 Alice 向 Bob 发主题 `第一封实验邮件`、正文 `你好`。
- 检查：正确设置后 Bob 邮箱中确有消息；错误密码在认证失败，不存在的收件人在收件/投递阶段失败；不显示成真实邮件已发送。
- 提示：看邮件停在哪一步 → 对应检查账号或收件人 → 给出模拟账户与服务端口。
- 挑战：发送给另一个已建立的本地邮箱，检查准确投递一次，不因重看结果重复投递。
- 完成/解锁：SMTP 操作状态、重复运行与邮箱持久化规则已定；仅服务器接受连接不能通关；TLS 若未实现必须标注简化认证连接。

### L-H03 把邮件从邮箱里读出来

- 状态/目标/前置：规划，依赖 IMAP 读取；前置 H02。
- 拓扑/配置草案：独立样板预置 H02 的一封邮件；Bob 电脑连接 `.30` 的模拟 IMAP 143，账户 `bob@office.example`、密码 `demo-only`，执行收取列表并打开邮件。
- 检查：读到预置主题和正文；关 IMAP 时不能读取，但 SMTP 投递仍可成功；Alice 凭据不能读 Bob 邮箱。
- 提示：能发送不等于能读取 → 查接收协议与账户 → 用 Bob 的模拟账号连接 IMAP 143。
- 挑战：新发一封再刷新列表，确认收件人、数量和内容，不以固定成功提示代替邮箱状态。
- 完成/解锁：权限隔离、消息身份、读取与重复刷新语义已有测试；不依赖用户必须先实际做完 H02 才能进入。

### L-H04 给另一个邮件域投递

- 状态/目标/前置：规划，依赖跨服务器 SMTP、MX 与转发限制；前置 H03、D03。
- 拓扑/配置草案：服务器 M1 `.10.30` 管 `office.example`，M2 `.10.60` 管 `partner.example`；DNS 配 MX `partner.example → mail.partner.example` 及地址 `.60`；M1 经模拟 SMTP 25 向 M2 的 `pat@partner.example` 投递。
- 检查：成功先查 MX、再连接对应邮件服务器并投递；缺 MX 或目标停服不同原因失败；不允许未授权客户端借 M1 向任意域转发。
- 提示：找收件域对应的服务器 → 分别查 MX 和地址记录 → 给出 MX 与 `.60` 记录。
- 挑战：错误转发配置导致拒绝时，只修需要的许可，不开放任意中继。
- 完成/解锁：MX、投递状态、拒绝转发、重试/重复消息边界已经确定；不得套用目前只支持单个地址记录的 DNS 模型假装完成。

### L-H05 让设备使用同一份时间

- 状态/目标/前置：规划候选，依赖 NTP 与确定性模拟时钟获批；前置 D02。
- 拓扑/配置草案：P3 SVC 提供模拟 UDP 123 时间服务，课程基准时刻固定；客户端初始偏快 5 分钟，时间服务器填 `.30`，发起同步。
- 检查：同步后显示课程服务时间与修正量；关闭时间服务或阻断 UDP 123 时不修改客户端模拟时钟；绝不改操作系统时间。
- 提示：看时间来自哪里 → 查服务与 UDP 路径 → 指定 `.30:123` 并开启服务。
- 挑战：另一客户端也同步，比较两台模拟时间一致，而非声称测得真实网络校时精度。
- 完成/解锁：先确定简化校时算法、状态保存和重跑语义；不得用 UDP 回显冒充 NTP。

### L-H06 把故障消息送到一个地方

- 状态/目标/前置：规划候选，依赖 Syslog 事件和接收端模型获批；前置 D02、H05（涉及时间对照时）。
- 拓扑/配置草案：P3 SVC 接收模拟 UDP 514；支持日志发出的 R1 配目标 `.30:514`；在课程内停用再恢复一条实验链路，产生具有事件身份、来源和模拟时间的两条消息。
- 检查：接收端实际出现对应来源和内容；阻断 UDP 514 后新消息未收到，不能只因本地有日志就报上报成功。
- 提示：先区分本地生成与远端收到 → 查上报目的地和通路 → 配 `.30:514` 并解除对应阻断。
- 挑战：两台支持上报的设备分别产生事件，在接收端区分来源，不重复制造已处理事件。
- 完成/解锁：事件触发、消息状态、收集与清理边界已确定；UDP 版本不承诺可靠投递或自动补发，也不顺带承诺 SNMP/SSH。
